# 生图和验收

## 把相貌保留下来的工作假设

默认使用视觉参考优先：原始照片提供完整的面部关系，每个孩子同时列少数双方五官线索供生成与核对。具体做法见 [双方相似、儿童感与局部修订](likeness-and-local-edit.md)。不要用通用的“圆脸、杏眼、圆鼻尖”替代人物本身，也不假定列更多部位就能提高辨识度。这是当前创作策略，仍需实际图像和用户反馈验证。

第一版“轮廓、眉眼、鼻部、嘴部四组各取一半”的工具保留作可选创作方法或对照，不再是默认路线。它只能表达设计意图，不能保证生成模型逐部位遵循。未经选择不把痣、疤痕、妆容或衣着当作可遗传特征复制。

儿童适配保留相对关系，重新形成对应年龄的面部体积和比例，避免把成年人的成熟鼻梁、下颌、皱纹直接缩小。本人儿时照片作为有来源的辅助信息，不保证“真实基因重现”。只有一方有儿时照时，将“复制了这一方小时候”列为专门失败项。

多视图的顺序：真人导入以原始主图为基础，默认增加一轮正侧面参考卡并与用户确认；虚构角色先选定候选，再为选中角色建立参考卡。细节见 [导入与命名](import-and-naming.md)。真人原始照片始终保留；生成侧脸不填补真实未知。额外视图的实际收益尚需比较，不能因它更完整就认为更准确。

## 首轮操作

1. 查看双方原图，区分整体面部关系、稳定可见线索和遮挡未知。文字观察存档，不必全部注入生成提示词。
2. 展示简短整体构思与每个孩子的双来源核对表；原图作为主要依据，有依据才指定局部关系。先明确本轮是比较面孔的合影还是生活瞬间，分别设计视线、活动和构图。
3. 用内置 image_gen 逐个生成。若参考组超过当前工具能完整处理的数量，优先每人一张主图，说明舍弃了哪些辅助图；重新生成引用顺序和对应提示词，不截断后仍沿用旧编号。
4. 对成图逐项检查并呈现给用户。先请用户自由说“哪里像谁”，再显示来源说明，减少提示诱导。
5. 用户指定候选或对最新结果给出明确问题时，说明编辑底图并围绕这些问题作一次局部修订，再看图。编辑授权不等于角色认可；不自动入库。
6. 候选展示时提出临时昵称，合并询问保留版本、外貌修改和名字。每个孩子单独确认；选中后再补参考卡，记录已确认名字，不反复询问。完整认可后提示下次可直接按名字调用。

家庭合照使用 visual_first 模板；单角色可直接按上述原则组织原图与简短提示词，保存真实载荷。用户明确选择第一版分组工具时才使用 `--assign brow_eye=A --assign mouth_smile=B`；不为满足旧版四组字段而补造未知特征。

## 第一轮验收

每张候选独立记录：

- 忽略头发和服装，每个孩子分别有哪些面部关系呼应 A？原图和成片的哪一处支持这个观察？
- 同一个孩子又有哪些面部关系呼应 B？不能以另一个孩子像 B 补足它的缺项。
- 年龄与自然程度是否达标？有没有成年脸缩小、怪异拼接？
- 发型是否符合孩子的日常造型，还是把成人的厚重偏分或定型发型缩小了？
- 目光是否有明确落点和自然反光，眼周与嘴角表情是否协调？不要把“别夸张大眼”执行成无神、僵硬或过度平淡。
- 是否只复制了一个来源，或与其他来源组合的结果过于雷同？
- 用户愿不愿意把它作为独立角色保存？

同时满足双方可指出具体锚点、年龄感合适且用户愿意保存，才算该候选通过。不能用同一个模型“自评很像”作为最终验收，不使用人脸识别分数冒充遗传真实性。用户的主观认可也不构成科学遗传验证。

每个判断拆成目标、实际观察、结论和不确定因素。相似度、儿童感与生活感各自记录；例如普通发型已实现，但四人仍同步看镜头，就不能写“已经像抓拍”。局部编辑还要记录保持项是否漂移，不能用提示词中的 preserve 当作保留成功的证据。

## 对照实验

当前优先验证童年参考的贡献，方法见 [家庭对照流程](family-portrait.md)。先用同一家庭两条件各一张做探索，保持实际提示词和工具参数一致，仅增加童年图。两张只是探索线索，需要重复采样才有机会判断稳定趋势。

| 条件 | 保持一致 | 改变量 |
| --- | --- | --- |
| 无童年图 | 同一成人图、提示词、年龄、发型、服装、场景和工具设置 | 仅提供成人参考 |
| 有童年图 | 同上 | 追加同组童年原图 |

随机打乱展示顺序，隐藏配方，先让熟悉双方的人自由写出相似点，再问是否愿意保留。保留失败图，记录每对通过数和偏好，不只展示最好的一张。生成器不暴露种子时明确不能配对像素种子，只比较重复采样结果。

第一轮先记录用户是否能在隐藏来源配方时具体指出双方特点，并排除发型、蛋糕、同款衣服或相似场景带来的熟悉感。成人保持、儿童比例、双方相似感与画面美观分开评价。若效果没有优势，保留失败结果，不先增加游戏系统。

后续分别做去掉儿时照、去掉文字锚点的消融；只有需要侧脸稳定性时才比较三视图。每次只改变一个条件，避免把更多重抽预算的收益误记到算法头上。

## 未来 App 和游戏

Skill 验证通过后，App 最小界面为建档、选两个来源、选择保留特征、三候选比较、认可入库五步。游戏层可增加“发现家族相似点”、角色收藏和多代外貌树。保存用户选过的特征与实际成图差异，价值来自连续创作，而不是自动公布真人家谱或虚构关系。

## 能力依据

截至 2026-10-24 核对的官方资料支持多参考图和图像编辑，同时明确跨次生成的人物一致性仍可能出错。这只能证明工作流有可用工具，不能证明本项目能保留双方特征。

- [OpenAI 图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)
- [图像编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)

Skill 使用当前内置工具，不承诺其底层模型或暴露 API 全部参数。未来改 API 时重新核对参数和账号可用性。
