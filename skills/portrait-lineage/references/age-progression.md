# 同一个角色长大

这条入口延续已出现的角色，使用角色自己的主图。它与“重新组合两个人产生一个新孩子”是不同任务；不能把父辈照片重新混合后冒充同一个孩子。

## 先确定人物与年龄

1. 结合当前对话确定“这批”“他们”的完整人物清单，分别列出名字 / ID、原年龄、目标年龄和主图。多名孩子必须逐个交付，不能因先做诊断而漏掉后面的角色。
2. “长大十岁”是每人原年龄加十：6 → 16、4 → 14。“长到十岁”是统一目标 10。两个意思不能互换；目标不大于原年龄时说明冲突，不静默逆龄。
3. 原年龄采用用户设定或档案 `age_years`，兼容旧字段 `age`。缺年龄时只询问缺失的角色，不凭外貌猜；近似年龄仍标“约”。用户希望比较多个年龄时，为每个目标年龄建立独立批次。
4. 已认可角色用 `characters.py resolve`。本轮用户指向的生成候选可用 `selected_candidate` 延续试验，记录所指图和原话，不为继续测试伪造已认可档案。没有名字时先给临时名；已确认的名字不要重问。
5. 一张合照支持多个孩子时，分别写 `selector` 明确各自位置与衣着，且在提示词排除其他人物。单人照也写“图中唯一人物”。不能把共享文件误认为同一角色，也不能把另一孩子当参考。

## 准备与执行

复制 [成长模板](../assets/age-progression-template.json) 到工作区 `portrait-data/`，填写实际名字、角色主图及年龄依据。候选文件路径相对方案 JSON；已认可档案路径仍相对档案所在目录。`identity_notes` 只填实际看图可见的少数辨识关系。

```sh
python3 "$SKILL_DIR/scripts/age_progression.py" prepare \
  --spec portrait-data/growth.json --profiles portrait-data/profiles \
  --output portrait-data/runs/grow-ten-years
python3 "$SKILL_DIR/scripts/age_progression.py" verify \
  portrait-data/runs/grow-ten-years/run.json
```

`prepare` 为清单中每人建立独立请求、原年龄参考哈希、名字与年龄、候选阶段记录和待填评审。整个清单校验通过后才写入新目录；不会修改人物档案，也不会调用模型。`verify` 检查输入与准备文件是否变化，不验证相貌或图片完成情况。

随后代理逐人实际查看参考图，按当前可用 `image_gen` 的参数执行保存的请求。默认每人一张单独照片，以便展示对应名字和年龄；如果用户明确要合照，可另组织合照请求，保留完整人物清单。不为节省调用自行减人。所有输入有路径时用 `referenced_image_paths`，不额外带入前几组家庭、父辈或未选中的参考卡。

每人保存结果、真实请求、工具返回信息和 `review.json`，再继续下一人。工具失败时记录失败人物和原因，继续能独立完成的项目；不得把 prepared 当 generated，或把未执行的请求称为成片。

## 如何让年龄增长仍然像本人

- 保留眼睑与眉眼关系、眼间距、鼻梁方向与鼻尖特点、唇线与嘴角走向；从儿童面部延续，避免换成通用少年脸或父辈年轻版。
- 成长体现在面颊体积、中下庭、鼻部长度与突出、下颌成熟度以及颈肩比例。年龄是整体观感，不靠换发型、制服或加胡须来伪装。
- 普通发型落实到剪裁、蓬松度、发丝和分缝，不加精心打理的卷束、棚拍妆感；保留明确的注视和自然细小眼部反光，不把有神误写成大眼睛。
- 先保证脸清晰，采用近似角度和光线。青春期个体差异大，无法保证看起来精确到某一岁；直接说实际画面仍偏小或偏大，不能把提示词年龄当观察结果。

分别检查：**同一个人吗、年龄感接近吗、造型自然吗**。若只是年龄偏小，保留身份重点调整比例和成熟度；若身份已漂移，回到原年龄主图重做。修订另存，比较非目标漂移；不要为了达成数字年龄无限迭代。

## 展示、确认和后续调用

交付逐人“名字｜原年龄 → 目标年龄”及对应图片，写出实际保持与变化，不能只给无名字的拼图。展示阶段可以附上原图对照。每位角色单独确认保留哪张，不把“整批不错”推导为所有阶段和侧面均获认可。

新照片默认是 `stage-candidate.json`，不放入当前 `profiles/`，不自动替换儿童主图。用户确认采用新年龄版本后，由代理备份旧档案并创建新版本，保留同一 `id`、已确认名字、原 `lineage` 和成长运行路径；更新年龄、选中主图及实际外貌评审，旧辅助视图失效后重审或记录明确跳过。**成长不增加家族代数，也不创建新的孩子 ID。** 目前阶段采纳由代理依据用户决定处理，脚本不自动提交阶段。

“调用小满”默认读取当前已认可版本；若用户指定“小满 6 岁时”，查历史版本及对应主图，展示准确版本再用。不能用 16 岁主图加一句“6 岁”冒充旧档案。当前名字脚本只解析当前档案，不提供年龄历史自动检索；历史选择由代理从运行清单、备份和图片核对。找不到明确年龄版本时如实说明，再按用户要求创作新候选。

历史 JSON 备份里的相对路径仍以原档案目录为基准；不要直接从 `history/` 位置解释路径，误判原图丢失。迁移数据时应连同图片、运行记录和原有相对目录一起搬移。
