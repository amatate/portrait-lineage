# 人物导入、多视图与命名

## 一次问清，边做边确认

首次导入先核对已有名字与原图归属，已经明确的不要重复询问。可以合并问：“这两位希望叫什么？昵称就可以；没想好我先用阿禾、阿川作临时名，等看图时一起确认。”没有名字不阻塞生成准备；助手起的名字先标为 proposed。两人不能共用一个人物 ID；合照按用户给出的名字与左右位置绑定，不根据面孔猜姓名。

向用户说明默认导入步骤：“我会多做一轮人物参考卡，每人一张正面、侧前方和侧面视图，供你确认并用于以后调用。目的是减少后续相貌漂移，实际效果仍需比较；没有真实侧照的角度会标成生成推测。”一轮指同一流程阶段，两个新人物通常是两次生成调用，不能说只多一次调用。已授权导入就继续执行，不再增加生图许可问题；用户要求快测或跳过时按其要求，并记下跳过原因。

## 参考卡怎样生成

1. 实际查看原图，挑最清楚的成人近照作为真人主参考。真实侧照存在时一并使用。童年照另存年龄辅助，默认不参与成人多视图，避免把成人年轻化。
2. 每人生成一张独立参考卡，默认包含正面、约 45° 侧前方、约 90° 单侧轮廓。不凭一侧照片推断左右对称；有明显不对称或用户要另一侧时再补。卡片中只出现这个人的不同视角，不能将两个人放入一张身份卡。
3. 统一头肩范围、焦距观感、柔和光照、普通衣服和背景。保持年龄、眼距、鼻部、嘴唇、下颌及原有辨识元素，保留纹理，不做美颜换脸。儿童卡使用同年龄日常发型、清楚但平静的注视和轻微自然表情；不为“有神”强制所有角度露齿大笑。
4. 明确这是同一人的多角度推测，正面也可能漂移。新角度不新增真人事实，不因为模型生成了鼻梁高度或下颌形状，就写进真人稳定特征。
5. 展示原图和参考卡，先由助手检查是否像同一个人，再让用户一次确认：“阿禾这个名字可以吗？正面像本人吗？侧前方和侧脸有哪些需要改？”允许只认可部分角度。使用 [参考卡评审模板](../assets/identity-review-template.json) 记录逐角度反馈。

参考卡提示词骨架：

> 用输入原图中的【明确位置】制作同一人物的三角度参考卡：正面、45° 侧前方、90° 侧面。三个视角保持同一身份、年龄、发型、衣着与柔和光照，普通头肩肖像，面部清楚。以真实照片为准，保留【一两项可见辨识关系】。没有真实照片支撑的侧面属于推测，不增添痣或疤痕，不美化换脸。自然清楚的目光、轻微表情。仅此一人，不混入其他参考人物。

先检查再展示；有具体错误时从原图和当前卡做一次针对修订。仍有分歧就保留 draft 或已认可的角度，不无限重抽。如果整张卡含被否定的侧脸，不能把整卡继续作为辅助参考；另生成仅含认可角度的干净图并检查，或暂只用原图。无需为了凑齐三视图把用户不认可的推测塞入后续请求。

## 名字、ID 与认可状态

- `id` 是不变的存储键，如 `character-20261025-001`；`display_name` 是用户可见名字，`aliases` 保存用户同意保留的旧名。命名采用昵称即可，不需要真实姓名。重命名不改 ID 和历史来源链。
- 没有指定名字时，给一个易记、与现有角色不重名的临时名。避开用长相猜民族、性格或真实亲缘来命名。用户说“就用你起的”才确认该名称，沉默不等于认可。
- `name_review` 单独记录名字的确认；`review` 记录主图/外貌认可；`identity_views` 记录参考卡的角度认可。任何一项仍待确认都不能伪装成完整可复用档案。
- 对于通常的完整导入，外貌、名字和可用视图得到用户确认后，将 profile 设为 approved。用户明确跳过多视图时，可记 `identity_views.status: skipped_by_user` 后用原始主图复用，不能假装侧脸已验收。只有正面获认可时，注明 `approved_partial`，不传被否定视图。
- “效果不错”是偏好反馈；上下文没有选定具体主图和名字时，不据此替用户定稿。

展示的角色卡至少包含：名字 / ID、真人或虚构、主图、年龄设定（如有）、双方来源（虚构角色）、已认可角度、尚未确定部分。下一次提示：“以后说‘调用阿禾和阿川’即可。”

使用 `scripts/characters.py list --profiles portrait-data/profiles` 查看角色；用 `resolve --profiles ... --name 阿禾` 按名字、别名或 ID 精确解析。这两个子命令只读本地档案，不做面孔识别，也不签署认可。遇到重名时展示 ID 和主图让用户选，不能取第一个或最近修改的角色。找不到时明确说明未建档，不凭名字重新捏一个人。

用户要求给已有孩子取名或改名时，用 `rename --name <当前名或ID> --to <新名> --confirmation <用户原话>` 记录；原话应来自用户实际选择，不由代理编造。仅确认名字不会批准外貌，也不要求重新生图。若用户明确希望旧名继续可调用，再加 `--keep-old-name`；否则旧名仅留在历史。命名风格（昵称、中文名、英文名、同系列名字）沿用偏好，无偏好可提 2–3 个容易区分的名字；不从姓名推断真实身份或血缘。

## 新角色和每一代孩子也要确认

生成候选后先显示结果，给孩子各提一个临时名。合并问：“保留哪个版本？哥哥暂叫小屿、妹妹暂叫小芽，名字要改吗？分别有哪些不像？”两名孩子各自有 ID、主图与状态，确认家庭合照不自动批准每个孩子。

用户选中并认可的孩子才进入建档：从选定图生成该孩子的独立参考卡，用同一套正面和侧面检查确认身份；名字已经确认就不重复询问。首轮不为所有未选候选做多视图。只看到家庭合照时，独立正脸的提取/再生成也需要检查，不能当成无变化的裁剪。

之后使用孩子自己的已认可主图及适用辅助视图，祖先资料仅用于追溯，不把所有祖先图堆进下一代请求。修改年龄、重要结构或主图时增加版本并检查相关视图是否过时；换衣服或一次表情修订不自动重建整个角色档案。让已有角色长大时走 [成长流程](age-progression.md)，同一个角色维持 ID，只有新一代角色才获得新 ID。

## 后续生成的参考次序

真人真实主图、真实同角度照片优先；虚构角色已认可主图优先。用户认可的生成视图是可选的姿态辅助，与主图同时使用，不能替换真人原图。儿童年龄转换可加入正确归属的真实童年图；生成的成人侧脸不能替代它。

只选本轮有用的少量参考：主图保证身份，需要转角度时补认可侧视图，需要儿童比例时补童年图。不把“多传图”本身当作质量保证。每张图在请求中写明职责；冲突时回到真实原图或角色主图。视图的用户认可表示接受创作参考，不把 `inferred_view` 改成 `current_photo`。
