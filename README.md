# 相貌继承实验室 · Portrait Lineage

一个用于 **Codex 的人像创作 Skill**：给人物建档、为虚构孩子取名，让同一角色长大，并通过名字继续调用。

重点是让每个新角色都能看出两个来源的具体面部线索，同时像年龄合适的普通人。它会先设计、再生成、看图检查、根据反馈局部修改，最后由用户选择是否保留。

**这是实验性的视觉创作流程，不是真实遗传或成长预测。** 它不识别人脸、不判断现实亲缘，也不要求两个外貌来源是一男一女。

## 能做什么

| 功能 | 可以这样说 | 会做什么 |
| --- | --- | --- |
| 导入人物 | “给这两个人建档，昵称你先取。” | 查看原图、区分图中人物、提议名字、建立草稿 |
| 正侧面参考卡 | “做正面、侧前方和侧脸，给我确认。” | 每人一张参考卡；推测角度与真实原图分开记录 |
| 创作孩子 | “用这两个人的特点，做一个 6 岁孩子。” | 为每个孩子安排双方的具体面部线索，再生成与检查 |
| 双孩与家庭照 | “一个 6 岁男孩、一个 4 岁女孩，来张家庭照。” | 保留人数与年龄约定，逐孩子检查是否呼应双方 |
| 孩子取名与建档 | “我认可第二张，叫小满。” | 记录选中图、名字和独立 ID，补参考卡或记录用户跳过 |
| 改名 | “小满改叫小舟，旧名字也保留。” | 保留 ID、备份旧版本、检查重名；旧名可作为别名 |
| 调用已有角色 | “调用小舟，换成在书店看书的照片。” | 精确查当前档案，用自己的主图继续创作 |
| 成长 | “这批孩子再长大十岁，每人一张，写上名字。” | 逐人计算 6→16、4→14；生成成长候选，保留儿童主图 |
| 局部修改 | “脸保留，只把头发改普通一点。” | 编辑选定照片，并检查未要求改变的部分是否漂移 |
| 多代创作 | “用已经认可的两个角色再组合一个新角色。” | 使用角色自己的主图，新一代有新的 ID 和名字 |
| 小红书草稿 | “把这次过程整理成一组分享图文。” | 整理结果、名字、真实迭代、AI 标识和正文草稿 |

这里的名字都是示例，不是仓库内预装的人物。**取名、视觉设计、看图、生图和用户确认由代理执行；脚本负责查档、改名、请求准备与记录检查。** 仓库不是独立 App，也不提供自动成功的“融合算法”。

## 安装与第一次使用

需要能读取本地文件的 Codex 环境。实际出图还需要环境提供图像生成/编辑工具；只安装 Skill 不会增加模型权限或免费额度。辅助脚本使用 **Python 3.10+ 标准库**，不需要额外 Python 包。

把下面这段发给 Codex：

> 请安装这个 GitHub 仓库的 Skill：`https://github.com/amatate/portrait-lineage`，路径是 `skills/portrait-lineage`。

如果环境带有内置 `skill-installer`，它可直接按仓库和路径安装。也可以下载仓库，把 `skills/portrait-lineage` 文件夹放入你的 Codex skills 目录（通常是 `~/.codex/skills/`；自定义目录以客户端配置为准）。已有同名 Skill 时先备份，避免覆盖本地修改。安装后在下一轮对话调用。

在一个用于存放照片和角色档案的工作目录里，提供你有权用于创作的照片，然后说：

> 使用 $portrait-lineage。先导入这两个人，没名字的话帮我取昵称。做正面和侧面参考卡给我确认；之后创作一个约 6 岁的孩子。我希望能看出双方的眼鼻嘴特点，发型普通，不要童模感。

完整导入会多用一轮生图做参考卡。它用于核对身份和辅助姿态，**不保证提高质量，也不能把生成侧脸当真人事实**。只想快速试效果时可以说“先用原图测试，不做参考卡”；测试不会自动变成已认可档案。

没给昵称不会卡住准备工作；助手可以先提名字，最终由你确认。名字、外貌和参考卡可以一起确认，也可以只保留某些角度。

## 为什么不只写“融合双方特征”

1. **每个孩子分别考虑双方。** 眼睑、眉眼位置、鼻部方向、唇线和嘴角比卷发、肤色或衣服更适合核对。忽略头发后，仍应能指出两方的线索。
2. **儿童化保留辨识关系。** 调整年龄结构和体积，避免所有人都变成圆脸、大眼、小鼻子的通用可爱脸。
3. **自然感要具体。** 普通剪裁、较低蓬松度、不齐刘海、局部压扁发丝，比只写“自然、凌乱”更可检查；具体造型仍按人物发质选择。
4. **以画面验收。** 提示词是目标。脸像不像、年龄合不合适、照片是否自然，分别写实际观察；不把“好看”当作全部达标。
5. **接近目标后局部修改。** 脸满意而头发太精致，就只修头发；整体不像才回原始照片重构。

同一人物的儿时照可以帮助理解儿童比例，但必须由用户说明对应关系。没有对照实验，不能把一次效果提升全部归因于儿时照。换来源人物后，重新确定参考清单，排除前一组照片与孩子。

## 从孩子到可复用角色

```text
提供原图 → 临时名字与人物草稿 → 参考卡 → 用户确认
                                 ↓
两个来源 → 设计每个孩子的特征 → 候选 → 选图、命名、确认视图
                                 ↓
                       已认可角色 / 固定 ID
                      ↙          ↓          ↘
                  换场景      同一个人长大     组合下一代
                  保留脸      保留 ID         新 ID
```

- “不错，继续”可推进已授权的测试，但不自动批准所有人物、名字和侧脸。
- 已认可主图与名字会保存；不认可的视图继续留作候选，不带入后续参考。
- “调用小满”读取当前已认可版本。找不到、重名、缺图或尚未确认时会说明，不重新捏一个同名人。
- 改名不重生成照片；成长不改变家族代数。成长阶段先保存为新候选，明确采用后再更新当前档案版本。
- “长大十岁”和“长到十岁”分开处理。缺原年龄时会询问，不能凭脸猜。若指定历史年龄版本，由代理核对历史图片与记录；当前查档脚本只查询当前版本。

更多完整对话示例见 [使用示例](docs/EXAMPLES.md)。

## 脚本与数据

用户通常直接用自然语言即可。需要检查本地记录时，在仓库根目录运行：

```sh
# 当前档案列表；包括草稿，但草稿不能自动成为正式复用来源
python3 skills/portrait-lineage/scripts/characters.py list

# 只解析已确认的角色，返回主图、图内位置和可用辅助图
python3 skills/portrait-lineage/scripts/characters.py resolve --name 小满

# 仅当用户确实说过以下改名要求时执行；保持外貌状态不变
python3 skills/portrait-lineage/scripts/characters.py rename \
  --name 小满 --to 小舟 --keep-old-name \
  --confirmation '把小满改成小舟，旧名字也保留。'
```

成长批次先复制 [模板](skills/portrait-lineage/assets/age-progression-template.json) 到 `portrait-data/growth.json` 并填写真实存在的档案/照片、图内位置与年龄依据，再运行：

```sh
python3 skills/portrait-lineage/scripts/age_progression.py prepare \
  --spec portrait-data/growth.json --profiles portrait-data/profiles \
  --output portrait-data/runs/grow-ten-years
python3 skills/portrait-lineage/scripts/age_progression.py verify \
  portrait-data/runs/grow-ten-years/run.json
```

这只会准备每人一份请求和待填评审；**不会自动调用生图，也不会批准新年龄主图**。代理随后执行请求、保存真实结果并展示。输出目录必须是新目录，避免覆盖历史。

## 隐私、边界与局限

- 仓库只含通用 Skill、模板、脚本和合成测试夹具，**不含真人照片、生成孩子照片或个人角色档案**。请自行提供素材。
- 默认数据保存在 `portrait-data/`，已加入 Git 忽略。忽略不是加密；使用云端生图仍会把选定参考发送到相应服务，这不是离线软件。
- 公开分享照片与本地创作是不同范围。准备小红书文案不等于执行发布；需要明确具体公开素材与发布指令。
- 相似度和年龄感仍可能失败，图像也可能过度美化。参考卡可能引入身份漂移；只使用你认可的角度，原图优先。
- 名字是本地索引，不是跨设备自动记忆。换电脑或工作区时，需要一起迁移档案、图片及其相对路径。
- 不进行身份识别、民族等敏感属性推断或真实遗传分析。所有儿童创作采用非性化、符合年龄的表现。
- 没有图像工具时，只能准备档案、设计与提示词，必须明确说明尚未生成图片。其他客户端或模型需要适配，未宣称通用兼容。
